一张图到底烧掉多少 Token？视觉 API 跨厂商计费机制拆解与图像降本清单

TokenNexus团队
2026-10-29 更新于 2026-10-29 阅读约 9 分钟

有做电商客服的团队复盘过一笔账：把商品原图（约 1500×1500）每次都带进多轮对话，一个月的 API 账单比只发文字翻了一倍多。他们一开始以为是模型贵，拉出 usage 才发现——图像 token 占了总输入的六成以上。这其实不是个例：视觉 / 图像 API 的成本，几乎全藏在"一张图被切成多少个 token"这个黑箱里。文本按字数估 token 还勉强靠谱，图像则完全看厂商的切块算法，差出几倍是常态。

下面把三家主流厂商的计费黑箱一个个拆开，再给同一张图做一次跨厂商实测，最后落到能直接抄的降本清单和一笔月度账。所有 token 数字都来自各家官方公式或官方文档示例，先讲清楚"钱到底怎么被算走"，再去谈省。

一、计费黑箱拆解：图像是怎么变成 token 的

OpenAI（GPT-4o / 4o-mini 视觉）。图像不走字数估算，而是走 detail 参数：detail=low 固定 85 token / 张，不管原图多大；detail=high 才进入切块算法——先把最长边缩放到 ≤2048px，再把短边拉到 768px，然后按 512×512 切块，每块 170 token，再加 85 基础 token。于是 1024×1024 会被处理成 768×768 的 4 块，共 765 token；而一张 512×512 的小图开 high，反而会被上采样到 768×768，同样是 765 token。OpenAI 官方那份视觉指南（prismix 整理的实测）也确认：1024² 在 high 下就是 765 token。

Claude（Anthropic）。Claude 的公式是线性的：token 数 ≈ 宽 × 高 / 750（在支持的上下文窗口内、无需二次缩放时）。套进去很直观：512×512 ≈ 349 token，1024×1024 ≈ 1398 token，1920×1080 ≈ 2765 token。Anthropic 官方文档给出的示例也吻合——200×200 约 54 token、1000×1000 约 1334 token。一句话：Claude 按像素面积线性计费，图越大几乎成比例变贵，没有"封顶"机制。

Gemini（Google）。Gemini 走"分块"逻辑：只要图片两个维度都 ≤384px，固定 258 token / 张；更大的图按 768×768 切块，每块 258 token。所以常见的 1024×1024 大约就是 1 块 = 258 token，比同样尺寸的 OpenAI high（765）和 Claude（1398）都低。这也是为什么社区里常看到"Gemini 处理图像比 GPT-4o-mini 便宜一个数量级"的对比——在 OpenAI 开发者社区的一个实测帖里，同一张 768×2048 图在 GPT-4o-mini 下被切成 8 块、约 4.8 万 token，而在 Gemini 2.0 Flash 下只有 258 token，差出约 31 倍。

二、同一张图，三家实测对比

把同一组尺寸丢进三家公式，差异一目了然（Claude 取线性公式、Gemini 取单块 258、OpenAI 取官方 high/low 算法）：

1024×1024765851398258

这张表里有三个反直觉的点：① 512² 和 4096² 在 OpenAI high 下都是 765 token——因为短边都被拉到 768，超大图不会更贵，但也不会更准；② 同一张 1024²，OpenAI high 比 low 贵 9 倍，而 Claude 比它再贵近一倍；③ Gemini 对常见尺寸几乎封顶在 258，是简单视觉任务最便宜的选择。选型时别只看"模型智不智能"，先看你发的是多大的图。

三、图像降本的五道闸

1. 默认 low，按需才 high。场景分类、物体识别、粗粒度打标用 low（85 token）通常够用，直接砍掉约 9 倍成本。只有读小字、看细线图表、辨细微纹理（发票 OCR、电路图、复杂表格）才上 high。上线前做一组 low/high 的准确率 A/B，比拍脑袋选 high 省得多。

2. 发送前先把短边压到约 1024px。OpenAI high 会把短边拉到 768，原图大于 768px 没有额外收益，先 resize 反而能避免把超大原图喂进去后某些路径多切块；Claude 是严格按像素线性计费，压尺寸就是实打实省钱。一张 4000×3000 的商品图，压到 1365×1024 再发，Claude 端能从约 1.6 万 token 降到约 1870 token。

3. 静态图做哈希去重与结果缓存。同一张参考图、同一张商品图被反复分析时，在应用层算图像哈希，命中就直接复用上次的分析结果或缓存的 token 账单。注意：图像不参与厂商的 prompt cache（缓存只对字节级一致的文本前缀生效），所以这层缓存必须自己做。

4. 非实时任务走 Batch 拿 5 折。文档批处理、夜间报表、历史图库打标这类没人等结果的活，用 Batch API 提交，输入和输出 token 都打 5 折，和上文的实时调用叠加能再砍一半。站内的 异步批处理降本指南 讲透了怎么接。

5. 选对模型：简单任务用低价视觉模型。Gemini Flash、GPT-4o-mini 这类按块计费、单价极低的视觉模型，对分类/打标绰绰有余；Claude 按像素线性计费，超大图慎选。和 Token 计费基础、中文分词器计费差异 里讲的逻辑一致——先看清"被怎么计费"，再谈优化。

四、三个最容易踩的坑

坑 1：小图开 high 被上采样反而更贵。很多团队以为"图小就 cheap"，结果给 512² 甚至 256² 的小图设了 high，OpenAI 把它上采样到 768²，照样 765 token，比 low 的 85 贵 9 倍。小图永远先 low。

坑 2：以为发 4K 图会更准。OpenAI high 把短边统一拉到 768px，传 4K 原图和传 1024² 在 token 上是一样的，模型看到的细节上限也一样。超出 768 短边的分辨率都是徒增体积、不增信息，还可能触发别处的缩放开销。

坑 3：把整本 PDF 的截图一次性塞进一个请求。OpenAI 单次最多 10 张图、token 逐张叠加，塞太多既烧钱又容易触顶。长文档拆页、逐页分析、必要时只发关键页，才是可控的做法。更多隐性成本坑见 AI API 隐藏计费陷阱。

五、算清一笔月度账

场景：某电商日均 1 万张商品图做分类 + 打标，平均 1024×1024，全部走 OpenAI GPT-4o 视觉（参考价输入约 $2.5 / 百万 token，以官方定价页为准）。

全 high：1 万 × 765 = 765 万 input token / 天，乘 30 天 ≈ 2.295 亿 token / 月，× $2.5 / 1M ≈ $574 / 月（仅输入）。

改 low：1 万 × 85 = 85 万 / 天，× 30 ≈ 2550 万 / 月，× $2.5 / 1M ≈ $63.75 / 月。光这一道闸就省约 $510 / 月，降幅近 89%。

再换 Gemini Flash（258 / 张）：1 万 × 258 = 258 万 / 天，× 30 ≈ 7740 万 / 月，按参考价 $0.10 / 1M ≈ $7.74 / 月。对只做分类打标的简单任务，这就是三个数量级的差距。模型智商不是唯一变量，"图被切成多少 token"才是视觉 API 账单的真正开关。想看各家实时报价与可用性，去 OpenAI 平台页、Claude 平台页、Gemini 平台页 对比。

结语

文本还能靠"字数估算"粗略预判成本，图像的成本则完全由厂商的切块算法决定，跨厂商差出几倍甚至几十倍都不稀奇。把 默认 low + 发送前压尺寸 + 静态图缓存 + 非实时走 Batch + 简单任务选低价视觉模型 这五道闸装好，多数视觉业务的图像成本能直接砍掉八成以上，而且几乎不伤效果。和 语义缓存、提示词缓存、长上下文优化 一样，视觉 API 的省钱本质都是同一句话：先看清钱被怎么算走，再决定怎么发。各家视觉计费规则随时在变，上 TokenNexus 首页 查最新官方价与选型建议。
